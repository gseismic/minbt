## 全仓纯减仓

全仓账户按整个分仓权益承担亏损，单一持仓释放的保证金加已实现盈亏可以为负。
纯减仓是数量与原持仓方向相反、绝对数量不超过原仓位的成交，不包含反手。

纯减仓在扣费后的分仓权益足以承担结算时允许形成有限的负现金余额。负余额表示已经实现的
现金欠款，由本分仓其他仓位的保证金与未实现盈亏支撑；get_cash 直接显示这个有符号余额，
不伪造零现金。成交仍记毛盈亏与手续费，随后立即按完整权益和剩余保证金检查风险。

欠款期间不允许新开仓、加仓、反手或向其他分仓划拨现金。纯减仓可继续执行，盈利腿平仓可
归还欠款。其他分仓返还非负现金可分次偿还 main 欠款；返还前检查接收现金及归档统计的有限性。
关闭非 main 分仓只能在仓位全部关闭并完成结算后返还现金，不能把欠款划给 main。
现金的一般支出、初始化与锁定接口继续保持非负限制；欠款结算只由账户内部的全仓纯减仓使用。
逐仓模式维持现有现金约束和独立风险结算。

普通全平先校验所有市场约束，再用副本计算每条腿的平仓金额和手续费，验证最终现金及记账
统计后一次提交整组持仓与现金。不能在组内某笔手续费扣除后提前触发免手续费强平，否则
相同仓位仍可能因顺序不同而产生不同费用。已在进入全平前被强平的仓位不进入计划；单笔
交易的即时风险检查继续保留。该规则替代 PLAN-067 的组内强平与后续 skipped 行为。

## 金额与候选状态

输入有限不等于运算有限。费用、释放保证金、已实现/未实现盈亏、成本、持仓数量、候选现金
和账户权益均在真实提交前检查；溢出报 ValueError，不能在异常后留下真实持仓或 pending 市价单。
候选持仓通过验证后一次复制到原 Position，保留查询者已持有的 Position 身份。

预检与现金提交共用零余额规则：只在现金加减两项的浮点间距所允许的少量尾差内归零，真实
超支仍拒绝；不使用会随余额任意放大的固定相对容差。所有候选现金结果必须有限。

## 时间与输入契约

- 内部退出省略 price，沿用既有报价；当前交易时钟用于成交、费用、撤单及风险记录。
- 独立 Portfolio 沿用已有报价的平仓保留原报价时间；用户显式提供新报价的无时间调用仍按原契约记录 None。
- iosql 的 dt 和显式 dt_ms 使用毫秒单位，普通 CSV dt 文本继续允许自动推断与 ISO 时间。
- 分仓名称必须是非空白字符串，校验在资金划拨之前完成；不对有效名称偷偷改写。
- 均线示例完整 Kline 使用 close_time 调度，open_time 只保留为原始载荷。
