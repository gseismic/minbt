## 用户场景与接口

| 场景 | 预计频率 | 保留的表达 | 必需行为 |
| --- | --- | --- | --- |
| 买入持有与固定目标 | 高 | order_target_size | skipped 可审计，每批不扫描历史订单 |
| 按价值或比例调仓 | 高 | order_target_value/percent | 风险推进后计算当前仓位和权益 |
| 清仓 | 高 | close_position 或目标归零 | 原持仓被强平后不得反向开仓 |
| 限价买入 | 高 | submit_limit_order | 成本按限价，浮盈亏按当前行情 |
| 修改持仓保护 | 高 | set_exit/add_exit/clear_exit(order.id) | 同一净持仓一份有效配置，按字段修改 |
| 跨市场沿用旧报价 | 中 | 默认 mark_price_missing='keep' | 当前时间校验休市与 T+1，报价时间独立 |
| 多周期/News 回放 | 中 | Bar、Feed 与已有回调 | 完整区间数据在完成时间可见，容器只读 |

频率是接口设计判断；不改变 Broker 常用方法签名，不新增下单转发或用户必须理解的交易计划对象。

## 订单与价格顺序

1. 归一化 symbol，校验 portfolio、有限实数、范围、时间和附带退出数值；纯报价解析不修改账户。
2. 合法显式价格更新报价并结算必要风险；省略价格则读取既有行情，保留其报价时间。
3. 目标和平仓按风险结算后的持仓计算差额；目标比例按更新后的权益计算。
4. Market 按当前交易时间校验交易单位、休市、禁空及可平数量，再预检保证金和手续费。
5. 提交数量、成本、现金和成交明细；恢复当前行情估值，立即处理成交带来的风险。
6. 更新订单状态、T+1 锁定与退出生命周期。成交后的强平不撤销已成交订单，另记风险结算明细。

非法参数抛 TypeError/ValueError，不修改报价、持仓、退出配置或盈亏。市场规则与资金不足用
rejected 表达；有效显式行情的风险推进仍是该接口已有行为，不把业务拒单当成撤销行情。
目标不变仍返回 skipped；显式价格即使目标未变也推进风险和估值。

Portfolio.submit_order 的 price/price_dt 为成交价和成交时间，内部附加 mark_price/mark_dt
为当前市场价和报价时间。独立 Portfolio 省略 mark_price 时沿用成交价估值。
Broker 使用已有报价传入 mark 参数，限价不覆盖 Broker/Portfolio/Position 的当前市场价。
成本、已实现盈亏和手续费按成交价计算；未实现盈亏及风险按市场价计算。
独立 Portfolio 的零数量请求返回 False，并且不推进报价、风险、资金或盈亏记账。
关闭分仓的预检和实际执行都表达全平目标，所有平仓金额与手续费整组结算，不在组内逐笔
触发风险。进入计划前已经清仓的标的不再生成旧数量订单；完成后撤销挂单、归还资金并归档分仓。
单笔全仓纯减仓在权益足够承担费用时可以形成负现金；欠款期间禁止加仓、反手及划出资金。
候选持仓、费用、现金和记账统计在提交前验证有限性；预检和现金提交共用浮点零余额规则。

## 时间与标的

- 当前交易时钟与 last_price_dates 分开保存。回放每个完整批次推进交易时间，包括只有其他标的或 News 的批次。
- 旧报价可按配置继续用于成交，但休市校验、订单/盈亏记录和 T+1 锁仓都使用当前时间。
- 内部退出不重发旧报价，独立 Portfolio 沿用报价平仓也保留时间；撤单采用实际状态变更时钟。
- 风险结算时间独立于报价时间；其他标的行情或较晚成交手续费触发清仓时，强平/穿仓明细也记录实际结算批次。
- 运行中显式 price_dt 不能改变回放交易时钟；手工账户的时间也不因旧报价倒退。
- 所有有效 symbol 是非空字符串，去首尾空白并转大写。归一化后检查重复市场路由；结果曲线查询采用同一规则。
- UTC 毫秒键以 epoch 差值的整数天、秒、微秒计算，不使用浮点 timestamp 后截断。
- 已约定毫秒的 iosql dt 与 dt_ms 不推断单位；分仓名称先校验非空白字符串，再划拨现金。

## 强平的提交边界

单仓强平先用 Position 副本计算释放保证金和已实现盈亏，再验证现金是否允许提交。失败不改变真实
Position、现金和记账。全仓强平先生成全部平仓金额，用 fsum 汇总并校验一次现金，再提交全部
持仓和现金；负权益持仓可由其他持仓补足，不能受字典顺序影响。实际记账保留每个标的的毛盈亏。

穿仓继续使用原模型：全仓清零并记录账户结算调整，逐仓只清零该仓。强平不新收手续费。

## 退出条件的所有权

同一 portfolio + symbol 的净持仓生命周期只有一份有效配置。当前生命周期的订单 ID 是修改句柄；
切换句柄时完整继承标准条件、追踪锚点、函数规则和 state，再覆盖显式传入字段。
规则列表归属配置，规则对象及其 state 属于整个持仓生命周期，切换句柄不重新运行 state 工厂。
新增函数规则也继承已有标准条件；选择性 clear 通过任一当前句柄作用于当前有效配置。

get_exit 返回指定订单当时的快照，历史配置保持 inactive；get_active_order 返回当前有效句柄。
函数上下文中的 order_id 随当前有效句柄变化。全平、反转和风险清仓立即结束旧生命周期，
无需等待下一次退出检查；旧订单不能新增、修改或清除新仓规则。退出检查只遍历当前配置。

## 行情可见时间与容器

Binance 下载、CSV、iosql 三个 reader 统一把 close_time 转成事件 dt，载荷保留整数毫秒的
open_time/close_time。00:00 开始的小时 Kline 在 00:59:59.999 发布。缺失或不晚于开盘的收盘
时间直接报错；不让 Exchange 推断通用 Bar 的时间含义。

请求 start/end 仍按 open_time 筛选 [start, end)，存储主键与覆盖区间仍按开盘时间管理。
Exchange 运行窗口按事件可见时间筛选。closed_only=True 控制数据是否已收盘且在收盘后下载；
closed_only=False 允许未收盘快照，但仍保守安排在该根 close_time 调度，不把快照解释成最终值。

Bar/News 的常见载荷容器冻结。on_bars/on_books 的外层映射也只读，on_trades 为只读映射加
Trade 元组，多个策略安全共享。需要修改时策略自己复制外层容器，原行载荷继续共享。

## 性能、缓存与资源

- 行情推进所需 symbol 从报价、持仓、挂单获取，不遍历历史 Order；T+0 不构造解锁标的集合。
- skipped 订单保留审计。目标策略的订单日志增长不再导致每批完整扫描，从而消除该路径 O(N²) 开销。
- 下载完整性检查包含首端、中间连续性和末端；非对齐 start 使用第一个开盘时间大于等于 start 的 Kline。
- 仅验证完整的区间写入 coverage。缓存读取重复验证，旧错误 coverage 无法静默放过缺失前缀，可 refresh 修复。
- 上市前空区间与下载截断无法自动区分，统一报缺数据，不虚构上市边界。
- SQLite 每次操作在事务提交/回滚后立即 close，正常、异常路径都不依赖 GC；Feed 无需保留连接。
- 通用 storage Feed 的 symbols 是筛选条件，允许部分命中；Binance reader 要求每个请求标的有行。
- 失效的 minbt.data.bars 已删除，不补兼容别名；具体 reader 仅从 minbt.plugins 导入。
