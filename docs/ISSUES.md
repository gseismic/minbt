# 问题清单

## ISSUE-001：增加库级盈亏统计接口

- **状态**：已完成（2026-10-11，PLAN-057）
- **涉及范围**：Broker、Portfolio、Position、回测结果查询
- **设计**：[库级盈亏查询](design/pnl-20261011-library-api.md)
- **计划与结果**：[PLAN-057](dev/PLAN-057-library-pnl.md)、[实施结果](dev/PLAN-057-library-pnl-OUTCOME.md)

### 原始现状

- `Broker.get_total_equity()` 和 `Broker.get_equity()` 可以查询账户权益；`Strategy.get_hist_equity()` 可以读取权益历史。
- `Position.unrealized_pnl` 可以查询当前持仓的未实现盈亏。
- 当前没有统一的公开接口查询已实现盈亏、累计手续费，以及按账户、标的或交易拆分的盈亏结果。
- `examples/000_core_pnl_sanity_check.py` 因此自行编写毛盈亏和手续费公式，并搭建回放逻辑来核对账户结果。

### 问题

盈亏计算和统计属于回测库的核心职责。用户不应在示例或自己的策略代码中重复实现这些公式，否则部分平仓、反手、手续费和多 Portfolio 等场景容易出现口径不一致。当前盈亏示例也承担了过多的计算和回放代码，掩盖了库本身提供的结果查询能力。

### 期望结果

设计并实现稳定的库级盈亏查询能力，明确账户净盈亏、已实现盈亏、未实现盈亏和手续费的定义及相互关系；按需要支持 Portfolio、标的和交易维度的结果查询。现有权益历史可继续作为净值曲线来源。

具体接口形态在设计阶段确定。实现及测试应覆盖多头、空头、手续费、部分平仓、反手和多 Portfolio 等情况，并保证盈亏统计与 Broker 权益变化一致。

`examples/000_core_pnl_sanity_check.py` 后续应改为展示库级接口的使用；手算公式和底层正确性验证放在测试中，避免在示例里重复实现盈亏计算。

### 完成结果

- 新增 `Broker.get_total_pnl()`、`get_pnl()` 和 `get_pnl_records()`，支持账户、分仓、标的和订单成交维度查询。
- `Pnl` 与 `PnlRecord` 为不可变快照，统一已实现毛盈亏、未实现毛盈亏、累计手续费及净盈亏口径；穿仓增加显式结算调整。
- 分仓划拨不计盈亏，已关闭分仓与同名重建历史继续保留原归属；预检与拒绝订单不污染成交统计。
- 示例已精简为库级接口和权益曲线展示，独立手算验证保留在测试中。
- 全量测试 257 项通过，覆盖多空、手续费、部分平仓、反手、多分仓、强平、穿仓和权益一致性。
