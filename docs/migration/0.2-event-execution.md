## 新默认成交语义

```python
from minbt import Strategy
from minbt import replay, sim

broker = sim.Broker(initial_cash=10_000)
exchange = replay.Exchange()
exchange.set_bars(prepared_rows)
exchange.add_strategy(MyStrategy("trend", broker=broker))
result = exchange.run()
```

市价提交返回 pending，在下一条该标的可执行行情撮合；只有 OHLC 时采用下一根可见 K 线的执行价。
不会使用当前缓存、其他标的事件或订单通知虚构成交机会。`execution_price="orderbook.bid_price"`
等显式配置可将执行价格源与估值 `mark_price` 分开。

同一个净持仓同时只允许一个变仓意图。相同未完成目标返回原 Order，改变目标返回
`rejected/target_in_flight`。目标金额和比例在请求时换算为固定数量，目标比例不自动乘杠杆。
平仓遇到未决意图先拒绝，调用方先撤单、等待事实与账户同步，再表达新的平仓目标。

用 `on_fill(fill)` 处理确认成交，用 `on_account(account)` 处理现金、持仓和就绪变化。
通知在当前策略回调返回后串行交付；Fill 不代表远端账户快照已同步。
新增 partially_filled、unknown、expired，unknown 不是终态。qty、filled_qty 和 remaining_qty 仍有符号。

所有环境的 on_init、预热/恢复、control、暂停时的账户通知和 on_finish 均只读。
需要启动下单的策略移到 on_ready；它在账户、保护与行情就绪后每个 run 最多调用一次。
可选 save_state/load_state 使用 JSON，恢复在 on_init 后进行，不 pickle 策略或函数。

## 旧历史模型

```python
broker = sim.Broker(initial_cash=10_000, execution="legacy_immediate")
```

此选项只复现旧成交时点与历史交易参数，不恢复 on_init 写账户等生命周期特例。
它只用于虚拟时间，不能配实时 Exchange。examples/02–17 的经济模型示例已显式选择此选项，
01_quickstart 和随包 quickstart 使用新的默认事件模型。

默认执行与实盘拒绝 price/price_dt 和逐单 leverage。市价由后续事实确认，限价使用
submit_limit_order；杠杆在模拟账户构造时配置，在交易所账户启动时核对，不在下单中偷偷修改。
旧根导入 minbt.Broker/minbt.Exchange 及 minbt.exchange.Exchange 暂作同类弃用别名，计划在 0.3 移除。

## 实时组件与 SDK 依赖

```python
from minbt.plugins.binance import live
from minbt import sim

exchange = live.Exchange(symbols=["BTCUSDT"], interval="1m", environment="mainnet")
broker = sim.Broker(initial_cash=10_000)
exchange.add_strategy(MyStrategy("paper", broker=broker))
result = exchange.run(control=read_control)
```

公共行情和执行账户独立装配。外部账户使用 live.Broker，environment 必填，另需 symbols、
account_id、state_dir 和凭证；首次状态目录要求账户空仓且没有未完成普通单/条件单。
首版外部模型限定 USDT 永续、单向、全仓、单资产保证金、main 分仓、单策略和固定标的。
历史 Exchange 拒绝外部账户，行情与账户身份/环境/标的不相容时在连接前拒绝。

Binance 插件需 Python >=3.10 和 crypto_api.binance2.usdm，核心仍为 Python >=3.8。
`minbt[binance-live]` 声明可选 SDK 依赖，核心及插件模块本身均不加载 SDK。
构造实时组件才检查依赖，网络资源由 run 创建和释放。

SDK 的 0.2.1 基线缺少逐请求最终发送许可。已在相邻 crypto_api 工作区实现并验证公开
`api.send_permission(check)`，本仓库同时保存可复现补丁：

```bash
# 在 crypto_api 基准 fbc4ab8 的源码目录应用，先核对已有工作区改动。
git apply /path/to/minbt/docs/integration/crypto-api-send-permission.patch
uv pip install -e /path/to/crypto_api
```

补丁未发布为新的 SDK 发行版；外部 Broker 会检查方法能力并拒绝缺少最终钩子的版本。
SDK 侧测试与结果见相邻仓库 docs/plans/PLAN-20261023-001-model-unknown-send-permission-OUTCOME.md。

当前 live 本地声明式保护会耐久保存配置、极值、阈值和退出义务。缺少可信离线路径时，
重启保留原阈值并阻止交易，需要明确处置保护基线；函数型退出不支持。
原生固定价保护仍待阶段 D 实施，当前选择 native 会明确抛 UnsupportedCapabilityError。

## 结果与停止

历史 `history_limit="auto"` 保留全量；实时默认保留最近 10,000 条历史。
显式整数同时约束策略历史、账户采样和可归档的终态订单/明细；活动订单与当前持仓退出句柄保留。
累计盈亏覆盖整个账本，窗口查询通过 history_truncated/retained_from 说明范围。

```python
result = exchange.run(history_limit=1000, result_dir=".minbt/results")

from minbt import PersistentResult
frozen = PersistentResult.open(".minbt/results", session_id=result.meta["session_id"])
orders = frozen.get_orders()  # 此时才从磁盘物化完整列表。
```

持久化结果按 session 和冻结截止序号查询；下一场运行不会改变旧结果。
未换算的非 USDT 手续费或缺失流水使 pnl_complete=False，完整盈亏查询抛
IncompleteAccountingError；订单、持仓、原始成交/流水与恢复路径仍可查询。
真正的数据损坏、磁盘或运行故障继续传播，不包装成正常的不完整账目。

exit 默认结束本地运行，保留远端仓位和委托。只在耐久未发送证明成立时取消本地意图；
已发送或结果未知的请求保留原 ID 核对。停止、close 和进程退出都不表示已平仓。
真实 demo 集成、原生保护竞争及全部设计验收尚未完成，不能据当前本机测试推断完整实盘已验收。
