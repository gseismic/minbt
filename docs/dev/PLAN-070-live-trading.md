## 边界与现状

- 核心 Python >=3.8；Binance2 插件 >=3.10，SDK 延迟加载。核心不导入插件。
- 首版外部账户只支持 USDT 永续、单向、全仓、单资产保证金、单账户、单策略、main 分仓和固定标的。
- 阶段 E（原生追踪、函数型退出恢复、多策略分仓、双向及跨币种）不在本次范围。
- 保留原有 PLAN-069 数值结算修复及用户设计稿、HANDOFF、BRAIN、GOAL 的工作区内容，不回滚、不混入提交。
- SDK 最终发送许可是外部交易的前置依赖；调用 SDK 前检查不能替代最终发送钩子。实施中通过受支持扩展补齐，不篡改 SDK 私有对象。
- 自动测试不使用真实资金；真实 demo 验证需要可用凭证，未经验证不能称已完成集成验收。

## 验证与交付

- 按用户最新要求，**先完成代码、自查并提交审阅；用户明确认可代码后才运行测试**。当前停止新增测试扩展与自动验证，不运行 pytest、Ruff、构建或其他验证命令。
- 认可后只运行与改动直接相关的必要测试，避免反复全量回归。已有测试记录仅说明当时版本，不代表最新工作区已验证。
- 每阶段自查，修复问题后再验证；最终生成 `docs/dev/PLAN-070-live-trading-OUTCOME.md`，如实区分本机验证与 demo 验证。
- 范围或实现步骤有变化先更新本计划。只提交本次实现，中文 commit 记录计划/结果路径与变更；按技能流程推送，失败时记录真实原因。

## 原生固定价保护的实施细化

实施第 15–16 项时，条件单使用独立 `algos` 耐久记录及 `protect` / `protect_cancel` 请求，
普通开仓订单的状态不接受条件单回执。记录原始 clientAlgoId、algoId、生命周期、配置版本、
方向、类型、closePosition 和触发价；经原 ID 查询核对后才关联 actualOrderId 和普通成交。
私有流早于关联的实际订单先隔离、关闸，由 REST 核对恢复，不能误记为开仓或重复成交。

同生命周期的数量变化保留固定价全平仓保护；替换先确认新单再撤旧单。
未知请求只查询原 ID；只有耐久未发送证明允许重新评估现有保护义务。触发后保留退出义务，
撤销剩余入场单并核对最后成交；剩余仓位由显式只减仓退出继续处置。
平仓后确认清理旧生命周期全部条件单才开放新仓。恢复发现未知归属或不合规载荷时只读诊断。

测试扩展为独立的远端条件单模型，核验 closePosition 的交易所端约束、实际普通单关联、
部分失败、超时查询、替换重叠、断线、触发与撤单竞争、清理屏障和重启恢复；
另以 SDK 本机 HTTP 捕获最终载荷，不能只断言调用便利方法时的参数。

原生保护验证后，补齐账户共用故障边界：Broker 实例启动采用原子认领，拒绝重复 run 时不改写首个会话；
标记价批次先整体校验有限正数，再更新投影。账户增加周期 REST 核对与单调时间同步年龄门禁，
即使私有流静默且无新行情也能核对流水，超期关闭许可；测试使用可控单调时钟。

第 4–6 项补充模拟部分成交扩展：`fill_quantity(order, price, dt)` 接收冻结订单与本次执行报价，
返回同方向的增量数量，零表示本次不成交，默认全成交；仅用于 next_event。
每个真实执行事件最多消费一次；累计 signed 数量、加权均价和逐笔费用独立记账。
部分成交仍占用目标，撤单释放剩余量，退出条件在首笔实际成交后即生效；同一 Broker 用于两种时钟。

恢复分页改为临时文件逐页交付，账户线程事务读取并释放，SDK/消费失败和会话关闭均释放未消费文件。
唯一成交插入时同步维护标的和订单累计数量水位，对账不再扫描完整成交历史；旧日志首次恢复时事务重建水位。

## 用户工作流调整（当前优先）

用户指示：“不要过分测试，在我认可代码后再测试”。后续先收尾实现与文档，整理具体变更供用户审阅。
尚未运行或中断的验证保持待办；未经用户明确认可代码，不恢复自动测试，也不把等待认可视为认可。
