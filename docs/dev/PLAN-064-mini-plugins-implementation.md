- 创建日期：2026-10-12（Asia/Shanghai）。
- 基准：`7ea1698`、minbt `0.1.1`；工作区已有 PLAN-063 设计文档，继续保留。
- 状态：已完成；见 [实施结果](PLAN-064-mini-plugins-implementation-OUTCOME.md)。
- 依据：[当前收敛设计](../design/kernel-20261012-protocol-plugins.md)。

## 目标与边界

完成用户授权的代码实施：集中协议、把现有具体读取/模拟交易实现迁入 `minbt.plugins`，保持旧导入及
运行行为，新增 `run(策略类, 配置, feed_factory=...)`，数据全部由用户准备。

不新增依赖、市场服务、注册表、Router、第二个回放循环或结果存储系统，不改版本。保留既有显式数据
下载能力的兼容入口，但新运行入口不自动选用任何数据源或发起网络请求。

## 实施前确认与小幅设计澄清

- 基准全量测试：334 passed；运行源码 29 个 Python 文件、6295 行。
- 协议模块只依赖标准库。数据记录用结构契约描述，现有 Bar/News/TimeBatch 的构造和时间解析实现保留，避免重写解析造成兼容变化。
- 旧模块转发为同一实现模块，保留私有 helper 的猴子补丁及对象身份，不复制交易和读取逻辑。
- 外部引擎负责返回冻结的 ResultProtocol 实现；默认入口返回现有 RunResult。只有查询接口不足以重建所有持仓历史，核心不自动重新缓存外部结果。
- 按需使用普通函数及现有资源关闭逻辑；配置/工厂失败也释放已创建资源。
- Feed 工厂实际支持列表和生成器，声明收敛为 Iterable，避免协议错误排除渐进装配。

## 验收

- 旧公共调用签名、默认参数、示例和金融行为等价；旧/新路径类与实现模块保持同一对象。
- 所有现有具体市场/存储/模拟交易代码唯一归属 plugins；协议不反向导入实现或数据 SDK。
- 自定义 Feed/默认 Broker、自定义 Broker 和纯信号配置均可运行；重复实验对象独立。
- 文件参数及 Mapping 参数可用，用户数据字段原样交给工厂，不猜路径或市场，不修改调用方配置。
- 开始/结束窗口、暂停/退出、工厂失败、准备/运行失败均有正确结果或异常与清理，无重复关闭和伪成功。
- 外部引擎通过协议直接注入，数据工厂不被核心重复调用，结果不强制转换成第二份账本。
- 自定义订单/Pnl 无需继承内置类，快照和查询容器修改不影响结果，缺能力和查询故障按原语义处理。
- wheel/sdist 和仓库外实际安装保留协议、插件、兼容入口及随包使用资源。
- 当前不新增 SDK、插件管理器、财务模型或输出存储，交付代码、中文文档、测试与 PLAN-064 结果。
